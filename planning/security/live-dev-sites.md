# Живі dev-сайти (G0-14) і SITE_DENYLIST (G0-13)

sl-security, 30.09.2026. Статус: **жоден сайт ще не відвідано** — мережа контейнера закрита (403), живий пас ⏭️.
Власник має право вето на будь-який рядок (не блокер). Додавання сайту — лише правкою цього файлу.

## Критерії допуску (G0-14, DEV-18)
1. Публічний, без логіну; аудит лише GET (шар 2), без форм/кошика/акаунтів.
2. Великий (CDN, витримує 1 аудит ≈ ≤ 12 сторінок × 2 viewport); не малий бізнес, для якого наш трафік помітний.
3. **Не** сайт §66 (G0-13; KREDENS у dev не використовується) і **не** сайти власника.
4. `robots.txt` дозволяє сторінки аудиту для `SiteLensBot` або `*` (перевіряє `audit:live` автоматично; Disallow → сторінку пропущено).
5. Етика: ≥ 1500 мс між навігаціями, 1 сторінка одночасно на хост, ≤ 5 аудитів на сайт за добу, чесний UA — `ethics.ts`.
6. Різні типи: e-commerce, сервіс, SaaS-лендінг, держсервіс/контент, сайт за бот-захистом (перевірка помилки §48, не аналізу).

## SITE_DENYLIST

- Джерело — env `SITELENS_SITE_DENYLIST` (у `.env`, поза репо): хост (`example.com` — з усіма піддоменами) або
  `sha256:<hex>` від імені в нижньому регістрі — щоб у спільному конфігу не розкривати сайт §66.
- Перевіряється двічі: `preflightLive`/`isSiteDenied` до запуску браузера (`scripts/audit-live.ts`) і в egress-проксі на
  **кожне** з'єднання (підресурси, редиректи, Lighthouse) — до резолву.
- Тести: `packages/browser/test/net-proxy-limits.test.ts` («SITE_DENYLIST (G0-13)»: парсинг, піддомени, sha256, `isSiteDenied`,
  проксі без резолву; контроль — без списку той самий хост проходить), `live-preflight.test.ts`.
- **Дія власника:** додати домен сайту §66 (коли назве) у `SITELENS_SITE_DENYLIST`, бажано як `sha256:…`
  (`printf %s domain.tld | sha256sum`). Доки не названо — список порожній (порожній список нічого не блокує; тест це показує).
