## 2. S1b — чесність чисел

- **«60 векторів»** — упаковка, не 60 незалежних доказів: 42 наскрізних рядки (v08 = 2 URL) + 9 «без слухача» + v52b + V14 +
  SW-1 + 4 рівня проксі + v37/v38 (не PASS, «відомий витік»). З канарковим контролем, що реально дійшов: **39**. Для v50–v58
  контроль «лог + 0 TCP» не може показати пропуск (слухача немає і в R0). Поріг ≥ 25 перекрито з запасом — критерій 1 на фікстурі
  виконано, але в документі писати «58 перевірених пунктів, 39 із наскрізним контролем канарки».
- **v26 (SW) у R1 — порожній PASS**: `attacker.test` по http → не secure context → `navigator.serviceWorker undefined`. Справжній
  доказ блоку SW — лише R5 і SW-1 (фікстура на 127.0.0.1). На живих HTTPS-сайтах SW API є — отже доказ = SW-1, не R1.
- **SW-1/DEV-48** — справжня знахідка, чесно показана на контролі (2 POST дійшли). Але це клас «JS-контекст, мережа якого не йде
  через `context.route`», і його закрито лише для SW: **SharedWorker того самого класу відкритий** (моя проба).
- Lighthouse за проксі: канарка 0, контролі 9/9 (без проксі і без `<-loopback>`) — підтверджено. Контроль без проксі показує
  `POST /lh-beacon`: під Lighthouse не-GET до **публічної цілі** проходить (DEV-12, прийнято). На HTTPS проксі метод не бачить —
  отже кількість не-GET від Lighthouse на живому сайті **неможливо навіть поміряти** поточними засобами.
- Етика: пауза ≥ 1500 мс доведена юнітом `HostGate`; у фікстурі `min_delay_ms: 0` (дозволено `fixture:true`), тож «пауза за
  логом» (кр. 4) на реальному лозі — ⏭️. Бот-захист §48 — на імітаціях, які писала та сама команда; справжній Cloudflare — ⏭️.
- Фікстура 7/7, clean 0, мутанти 7/7, стабільність 3/3, метаморфні 24/24 — чесно позначено «регресія того самого автора, не
  held-out». Єдиний held-out досі — twin-2 6/7 (S1a).
