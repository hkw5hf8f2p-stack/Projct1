# Запечатаний held-out корпус guard-а (S4, G0-15)

Автор: sl-critic, 30.09.2026. Імплементатор guard-ів (структурне правило S4 + лексичний guard) **не бачить**
`cases.jsonl` до прогону. Корпус написано без читання коду guard-ів і без читання спаленого
`planning/eval/hostile-heldout/cases.jsonl`. Хеш: `../guard.sha256` (`sha256sum planning/sealed/guard/cases.jsonl`).

## Склад
100 кейсів: 52 `reject` (26 uk + 26 en) і 48 `pass` (24 uk + 24 en). Формат рядка JSONL:
`{id, lang, field, text, expected: reject|pass, category, evidence_values}`.

`evidence_values` — **додаткове поле**: числа, які код підставив би з доказів/скорингу для цього тексту (білий
список структурного правила з висновку S3). Прогін мусить передавати їх як білий список; якщо guard-конвеєр білого
списку не приймає — це саме по собі FAIL структурного рішення S4. Шаблонні літерали «/100» у «Priority NN/100» і
N, M у «N of M synthetic …» включені в `evidence_values` явно.

Категорії `reject` покривають усі п'ять класів пропусків S3 (DEV-47: multiplier, uplift/revenue paraphrase,
share без %, fake benchmark) + TAM/частка ринку перефразовані, словесні числівники з відмінками, демографію без
ключових слів, число не з доказів, синтетичні лічильники як частка людей, вигаданий social proof у копії варіанту.
`pass`: «N of M synthetic …», «Priority NN/100», OBSERVED-виміри, BENCHMARKED-пороги (CWV, WCAG), ціни сайту, дати,
viewport, лексичні пастки (TAMPA, Share, Market), якісні рекомендації, UNKNOWN, порядкові («перший екран»).

## Пороги (критерій виходу S4 №4)
- Recall на `reject` **≥ 90 %** → не менше **47/52**.
- Pass-rate на `pass` **≥ 90 %** → не менше **44/48** (хибних відхилень ≤ 4).
- Обидва пороги рахуються на всьому корпусі; додатково звітуються (інформативно) розбивки uk/en і за `category`.
  Будь-яка категорія `reject` із recall < 2/3 іменується в conclusions як відомий пропуск (без текстів кейсів).
- «Відхилено» = текст не дійшов би до користувача в поданому вигляді (reject / regenerate / видалення речення з
  позначкою). Перефразування guard-ом із числом, якого немає в `evidence_values`, = пропуск.

## Процедура
1. Прогін **лише після** тегу/коміту заморожування guard-ів S4 (структурне правило + лексичний guard); хеш тегу
   записується в артефакт прогону.
2. Перед прогоном: `sha256sum planning/sealed/guard/cases.jsonl` == `planning/sealed/guard.sha256`; після — те саме.
3. Прогін **одноразовий**, без правок guard-ів між читанням корпусу й підрахунком. Результат (по кейсу: id,
   expected, actual) — у `planning/qa/artifacts/sprint-4/`; у conclusions — лише числа, категорії й SHA-256.
4. Після прогону корпус **спалено**: будь-які подальші правки guard-ів, що використовують його, роблять повторні
   прогони лише інформативними; наступний критерій потребує нового корпусу від не-автора.
5. Прогін детермінований (без LLM): guard — код. Живі тексти моделі — ⏭️ live pass (S7), цей корпус їх не замінює.

## Спірні рішення (очікування задав критик; оскаржується через DEVIATION_LOG, не правкою корпусу)
- **«Удвічі швидше завантаження (Lighthouse)» / «twice as fast»** → `reject` (`multiplier_forecast_perf`): це прогноз
  результату зміни, а не вимір; кратність не походить із доказів. Прийнятна форма — два виміряні числа
  (див. pass «LCP 4.8 s … поріг 2.5 s»), без обчисленого моделлю відношення.
- **Якісні прогнози без чисел** («more visitors will reach checkout») у корпус не включено як `reject` — межа
  між прогнозом і гіпотезою залежить від формулювання; кейси `share_no_sign`/`multiplier` без цифр включено, бо
  вони несуть кількісний зміст словами (половина, більшість, у кілька разів, кожен четвертий).
- **Персона з віком / демографія без ключових слів** («Martha, 34, office manager», «молоді мами») → `reject`
  (SPEC: lens ≠ demographic persona). «34» не з доказів — ловиться й структурно.
- **BENCHMARKED-пороги** (CWV 2.5 s / 0.1, WCAG 4.5:1) → `pass`: опубліковані стандарти, числа подані в
  `evidence_values`. Вигадані «середні по галузі» без джерела → `reject`.
- **«7 of 10 synthetic journals …» у `finding.title` без застереження про одну модель** → `pass`: застереження
  (G0-25) — перевірка рівня звіту/UI, а не guard-а речення; у `report.summary` кейси із застереженням.
- **Порядкові й «перший екран»** → `pass`: структурне правило, що рубає будь-який числівник, мусить відрізняти
  порядкові/службові слова, інакше false-reject.
- **Ціни й пороги, процитовані з сайту** (у т. ч. в `variant.copy`) → `pass` лише тому, що значення є в
  `evidence_values`; вигаданий social proof («10 000 клієнтів») → `reject`.
