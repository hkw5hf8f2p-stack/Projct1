## Що вирішує код, що — LLM
| Рішення | Хто | Де |
|---|---|---|
| Згенерувати 18 кандидатів (числа 0–1 або `"unknown"`, опис, мета, питання, заперечення) | LLM (`lens-generator-v1`) | `generate-lenses.ts` |
| Відкинути демографію / «% ринку» / англійську в uk-аудиті / ін'єкцію / поза 0..1 / зайві поля | код (guard-и `guards/text.ts`, Zod) | кандидат відкидається з позначкою, набір лишається |
| `unknown` → 0,5 + прапорець `unknown_var:<lens>:<var>` | код | `candidateToLens` |
| Дедуплікація (d < 0,15 ∧ схожість цілей ≥ 0,6), полюси P1–P7, farthest-point, вибір 12 (8–20) | код (C5) | `lenses/select.ts` |
| Відсутній полюс серед кандидатів → ОДИН додатковий запит (~6 лінз лише під ці полюси) → якщо знову нема, `pole_unmet:Pn` + найближчий кандидат | код ініціює, LLM генерує | `generate-lenses.ts` |
| `task_type` кожної задачі | LLM класифікує (з переліку), код перевіряє enum | `generate-tasks.ts` |
| Релевантність r(lens, task), матриця 24–40, журнали 8+8, пристрої | код (§10, без LLM-виклику) | `matrix/build.ts` |

Полюси (§9.3): P1 novice (ck ≤ 0,3) · P2 expert (ck ≥ 0,7) · P3 price-sensitive (ps ≥ 0,7) · P4 price-insensitive (ps ≤ 0,3) ·
P5 fast (ds ≥ 0,7 ∧ dp ≤ 0,5) · P6 research-heavy (ds ≤ 0,3 ∧ dp ≥ 0,6) · P7 skeptical (tr ≥ 0,7 ∨ ra ≥ 0,7).
Полюси поведінкові; жодної демографії й відсотків населення (§8, §63) — це перевіряють guard-и та ворожі H19–H24.

## Відомі обмеження (чесно)
* Випадкові набори не моделюють кореляцію змінних у реальних лінзах; частота `pole_unmet` на виході живої моделі — ⏭️ (S7).
* Дедуплікація за схожістю цілей — токени-стеми довжини 5, груба для uk; хибні збіги/пропуски на живих текстах — ⏭️.
* `matrix_overflow` за межами домену (> 7 задач) не гарантує розмір ≤ 40 (12 важливих задач дали 41 → `size:41` у `violations`, не приховано).
