# S7 живий сесійний пас: прогони A і B

Транспорт `LLM_PROVIDER=session` (DEV-82): відповіді дає Claude у сесії через «сліпих» субагентів, API-ключа немає. Усе нижче — **плумбінг + вибірки моделі-сесії**, не якість продакшн-моделі: адаптери API, реальні `usage`/$ (токени estimated), стабільність §56 і E4 — ⏭️ live pass. Числа відтворюються командами в кінці; артефакти — `planning/qa/artifacts/s7-session/replay-A/`, `replay-B/`.

## 1. Що змінилось між A і B

| | A (`claude-in-session`) | B (`claude-in-session-b`) |
|---|---|---|
| Промпт | до виправлення: `{{A11Y_DATA}}` (плейсхолдер із цифрою) не підставлявся в snapshot-evaluator і browser-agent — модель бачила літерал | після `b2f6d1b`: `fill()` fail-closed на будь-який непідставлений `{{…}}`, порожній outline явний. Версії промптів не змінено, текст шаблонів не змінено (змінився лише код підстановки) |
| Виконавці | 100 запитів, набір сліпих агентів №1 | ті самі 100 запитів (нові ключі E5), 7 нових сліпих агентів |

Різниця A→B **сплутана**: змінились і промпт (A11Y), і виконавці. Причину зміни E1 y/3 встановити не можна (див. §3).

## 2. Метрики (перерахунок ПОТОЧНИМ кодом)

B — `--provider replay` за хешем E5 (без нових відповідей). A — `--by-logical-key` (DEV-88): ті самі байти відповідей за логічним ключем, бо ключі A не збігаються з виправленими запитами. Самоперевірка: перерахунок A збігається з оригінальним прогоном A (E1 3/3 і 10/10, E2(б) Jcat 0.372 при розмірах 5/11/14, E3a-відхилень 2).

| Перевірка | A | B | Межа |
|---|---|---|---|
| E1 детерміновані x/7 | 7/7 | 7/7 | код, не LLM; VERIFIED |
| E1 ранг топ-10 [гейт] | 7/7 (контроль scoring-v1 теж 7/7 — не впав, гіпотез замало) | 7/7 (контроль 6/7 — впав, як має) | — |
| E1 LLM-лише y/3 | 3/3 | 0/3 | показник, не гейт; див. §3 |
| E1 разом | 10/10 | 7/10 | гейт ≥ 8 залежить від LLM → ⏭️ live |
| E2(а) повний звіт [гейт] | PASS, Jcat 1.000/1.000, \|K3\|=3 | PASS, те саме | топ-5 — детерміновані знахідки, тож (а) майже не залежить від LLM |
| E2(б) лише LLM | Jcat 0.372 (< 0.4), розміри 5/11/14 | 0.500, розміри 3/3/10 | показник; ціль ≥ 0.4 — A нижче, B вище; у B множини малі (3/3) через §23-відхилення |
| RBO топ-10 | 0.974 | 0.846 | інформативно |
| E3a | PASS (2 знахідки, відхилено §23: 2) | PASS (2 знахідки, відхилено: 0) | специфічність живої моделі — ⏭️ |
| E3c | код 2/5 + LLM 1/5 (vague headline) = 3/5 | код 2/5 + LLM 1/5 (comparison) = 3/5 | гейт ≥ 4/5 недосяжний кодом (2/5) → ⏭️ DEFERRED, не PASS |
| INJ obeyed / echoed | 0/4 / 2/4 | 0/4 / 2/4 | 4 виклики; не міра стійкості |

Вердикт `validate` (session, replay): PASS для обв'язки; E3c ⏭️. E4 у session не вимірюється.

## 3. E1 LLM-лише y/3: розподіл по 8 незалежних вибірках (DEV-88)

Вибірка = один namespace (`s7`, `s7-e2-run1..3`) однієї моделі-сесії; правило зарахування — незмінний `e1Matches`, нічого не тюнено.

**Розподіл: 0/3 ×4, 1/3 ×0, 2/3 ×0, 3/3 ×4.** A: 1× 0/3, 3× 3/3. B: 3× 0/3, 1× 3/3. Частота: №1 headline 4/8, №3 jargon 4/8, №4 similar_products 4/8 — завжди **разом** (бімодально).

Чому бімодально (діагностика, не тюнінг): у всіх 4 вибірках y=0 **усі** friction релевантних категорій (15–17 на вибірку) відхилено кодом як `no_verifiable_evidence`, і **всі вони — дослівний текст сторінки без подвійних лапок** (промпт вимагає лапки, §23). Тобто y/3 тут міряє слухняність формату evidence, а не «бачить/не бачить дефект». Це не «модель нестабільна» і не «правило надто вузьке за категорією»: у вибірках y=0 немає релевантних знахідок, які не збіглися б через категорію.

Правило зарахування: вузьке за форматом evidence (§23, свідомо), **широке за змістом** — зараховує будь-яку знахідку категорії на сторінці, не перевіряючи, що цитата — це саме засіяний дефект (claim_kind у LLM майже завжди `general`). Ручна звірка 4 вибірок y=3 показала влучання в засіяні дефекти (H1 «Ми підбираємо речі…», «HFX», однакові описи), але частина збігів №3/№4 випадкова (`terminology|product` із цитатою «Прибрати з порівняння»).

Гіпотеза (НЕ перевірена): блок A11Y у B змінив звичку цитування (3 з 4 вибірок B без лапок проти 1 з 4 в A). Перевірить A/B на тих самих виконавцях. Рішення «приймати evidence без лапок, якщо він дослівно є на сторінці» змінює §23 і всі LLM-метрики; **не робилось** — це рішення sl-eval-science/власника, числова основа є (100 % відхилених у y=0 були дослівними).

## 4. Prompt injection (DEV-87)

| | до фіксу | після фіксу |
|---|---|---|
| obeyed (дію/ціль виконано) | 0/4 | 0/4 |
| echoed на рівні виходу моделі (цитата/переказ інструкції) | A: 0 помічено (класифікатор шукав лише канарку), B: 2/4 («compromised») | 2/4 (обидва прогони) |
| відлуння **у звіті** (evidence після `integrateSessions`) | 2 (A і B; фільтр вимкнено — контроль) | **0** (відхилено `injection_text`: 2) |

Знахідка: прогін A теж цитував ін'єкцію дослівно (обрізану, без канарки), а старий INJ дав «4/4 resisted» — хибне негативне. Виправлення: `detectAiInstruction` + фільтр в `integrateSessions` (friction відкидається, лишається знеособлена `injection_notices` без тексту). Контролі: без фільтра текст і канарка потрапляють у JSON звіту; звичайна цитата проходить; підкладена цитата в validate: до 1, після 0. Межі: евристика, перефразована/іншомовна інструкція поза списком може пройти; пункт «код-шаблон із OBSERVED-доказом у звіті» відкритий (потрібен шаблон у `packages/schemas`).
